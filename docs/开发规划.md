### 项目说明：

每日 To-Do List 网页应用。用户可以在应用中添加、删除、完成待办事项。用户可以通过邀请码加入群组，群组成员之间可以实时看到对方每日 To-Do List 的所有数据（相互监督）。

### 技术栈：

- 框架：Next.js (App Router)最新版本, TypeScript, Tailwind CSS, shadcn/ui，zustand作为状态管理库。
- 数据库：PostgreSQL（image: postgres:16-alpine） + Prisma ORM。
- 部署：使用 Docker 容器化部署（Node.js 环境）。

### 数据库结构 (Prisma Schema 参考)：

请基于以下核心模型进行开发（可根据需要补充字段）：

- User: id, username, passwordHash (加密存储)
- Group: id, name, inviteCode (唯一随机码)
- GroupMember: userId, groupId, joinedAt (多对多关联)
- Todo: id, content, isDone(布尔), targetDate(日期), userId

### 核心功能与技术规范：

1. 【认证系统】
   - 使用自定义 JWT 认证（无 refreshToken，单 accessToken 即可）。
   - ⚠️ 关键：登录成功后，接口返回 JWT 字符串，前端负责将其存储在 `localStorage` 中。
   - 前端需封装统一的 Fetch 请求（或使用 axios），在后续所有请求头中携带 `Authorization: Bearer <token>`。
   - 页面路由保护逻辑需在客户端处理（例如在全局 `layout` 或高阶组件中检查 `localStorage` 的 token，无 token 则重定向到登录页）。
   - 使用nextjs中间件进行未登陆拦截。

2. 【个人待办 (CRUD)】
   - 实现按日期（今天/历史日期）查看和添加任务。
   - ⚠️ 关键：由于采用客户端鉴权，相关业务组件需声明为 `'use client'` 并在客户端获取数据。
   - ⚠️ 关键：在勾选完成/取消完成任务时，前端必须实现"乐观更新（Optimistic UI）"，确保操作的秒级反馈（UI 先变，再等接口返回确认），避免卡顿感。

3. 【群组与实时同步 (SSE)】
   - 用户可创建群组并生成邀请码，其他用户输入邀请码加入。
   - 群组详情页展示当日所有成员的 Todo 进度（卡片网格布局）。
   - ⚠️ 关键：使用自定义 Server-Sent Events (SSE) 实现实时刷新。
   - 建立专属的 Next.js API Route 提供 SSE 流（建立连接时需通过 URL Query 或其他合法方式校验 Token）。当前端收到其他成员更新的 SSE 消息时，触发页面数据的重新拉取。前端需实现基本的 SSE 断线自动重连逻辑。

4. 【前端页面与 UI/UX】
   - 包含：登录/注册页、个人看板页、群组看板页。
   - 风格要求：极致简约，操作直觉化。配色要求"清新、符合春天自然气息"（例如使用浅绿、薄荷绿、暖白等色系搭配 shadcn/ui 的 CSS variables）。

5. 【代码质量要求】
   - 严格遵循 TypeScript 类型安全，避免使用 `any`。
   - 业务逻辑与 UI 组件分离，代码结构清晰，拒绝冗余。
   - 提供必要的代码注释，尤其是在封装 Token 请求拦截和 SSE 连接的部分。
   - 提供一份基础的 `Dockerfile` 用于项目构建和独立部署。
   - 目录结构清晰，符合 Next.js 最佳实践。
   - 组件化开发，避免重复代码。
   - 开发前请选基于前端设计skills作为参考指导。
